# ARA VPN 0.1.1 · Debian

## Установка и первый запуск

1. На новом Debian выберите роль. Если хотите панель с сервером, используйте `server`. Для одной панели — `control`. Для дополнительного выхода — `edge`. Для клиентской установки — `client`.
2. Скопируйте команду со страницы выпуска GitHub и выполните её в терминале Debian. Для проверки без установки уберите `sudo` и `--setup-panel`. Нужны curl, OpenSSL, iproute2 и systemd для мастера панели.
3. В мастере введите домен или IP. Enter выбирает `127.0.0.1`, порт **29445** и локальный сертификат. Для доступа из другой сети подтвердите внешний слушатель и разрешите выбранный TCP-порт в своём firewall.
4. Выберите сертификат. Локальный подходит без домена, его нужно добавить в доверие на клиенте. Для Let’s Encrypt укажите публичный домен, настройте DNS и освободите входящий TCP 80 на время HTTP-01. Свой сертификат импортируется двумя путями PEM. Если 443 уже занят, панель по умолчанию использует отдельный 29445. Встроенный непривилегированный слушатель принимает порты 1024–65535. Для 443 используйте HTTPS-прокси. Для ACME выпускается первый сертификат, настройка планового обновления остаётся отдельным действием.
5. После проверки TLS мастер выводит **полную ссылку, логин и пароль**. Если панель оставлена на loopback, откройте её на сервере или через SSH-туннель. Запишите реквизиты в менеджер паролей.

```sh
curl -q -fsSL --proto '=https' --proto-redir '=https' https://raw.githubusercontent.com/ARA-VPN-Project/ARA-VPN/main/install.sh | sudo sh
```

Команда запускает мастер серверной роли. При запуске из root-сессии замените `sudo sh` на `sh`. Нужны curl и системные утилиты из списка выше. Корневой launcher поддерживается в main и сейчас устанавливает закреплённую версию 0.1.1: скачивает bootstrap по HTTPS, проверяет его SHA-256 и передаёт закреплённый хеш архитектурного manifest. Затем проверяются пакеты и их идентичность.

Для другой роли используйте `sudo sh -s -- edge`, `control` или `client` в конце команды вместо `sudo sh`. Для проверки без установки сохраните корневой install.sh и запустите `sh install.sh server --check`. Есть amd64 и armhf; другие архитектуры не выбираются молча.

Чтобы получить адрес и реквизиты штатной панели после установки:

```sh
sudo -u ara-control ara-control --state-dir /var/lib/ara-control --admin-credentials
```

После смены пароля в настройках команда показывает адрес и имя пользователя. Новый пароль хранится в виде проверочного значения. Перед обновлением сохраните состояние панели, конфиги, сертификаты и ключи. Используйте подписанный updater с закреплённым корнем доверия. Пакетная установка поверх ручного развёртывания требует отдельной миграции.

## Панель, две ноды и подписка

1. На внешней ноде настройте выход и подготовьте TLS для тех слушателей, которые используют TLS. С доменом проверьте DNS и доступность ACME challenge. Без домена настройте частный CA и доверьте ему на обоих концах или используйте локальный HTTP для администрирования через SSH. Удалённым клиентам выдавайте достижимые HTTPS-ссылки с доверенным сертификатом.
2. На входной ноде настройте клиентский слушатель и его сертификат. Оставьте публичный корень нейтральным. Секретный адрес панели и учётные данные получите локально из установленного `ara-control --help` и команды `--admin-credentials` с каталогом состояния панели. Храните их раздельно от подписок.
3. В панели добавьте выход и связь Edge → Exit. Сверьте адрес, протокол и проверку TLS. Связывание панелей делайте отдельным одноразовым административным приглашением с минимальными правами. Проверьте трафик через каждый выход.
4. В «Маршрутах» выберите выходы для нужных доменов и сетей. Выберите маршрут по умолчанию и поведение при отказе. Для строгого профиля назначьте конкретный выход и проверьте, что его отказ блокирует поток. Превью правила сверяйте с реальным запросом через Edge.
5. В «Доступе» создайте пользователя и подписку, добавьте доступные конфигурации и лимиты, затем откройте «Ссылка и QR». Для стороннего клиента выберите совместимый экспорт. Проверьте загрузку подписки, установление туннеля и фактический IP выхода отдельно. Храните ссылку как учётные данные.
6. Проверьте статус юнитов, публичный TLS, короткий запрос через каждый выход и доступ к управлению. Зафиксируйте время, результат и идентификатор версии. Секреты и приватные адреса в публичный журнал не включайте.

## English quick start

1. Choose the Debian package role: client, edge, control or server.
2. Use the version-pinned command above. The wrapper checks the downloaded bootstrap hash and pins the architecture manifest; the bootstrap verifies package checksums and identities. The one-command example installs packages and starts the panel wizard. Accept the defaults for loopback HTTPS on port 29445, or enter a hostname or IP and choose local TLS, domain ACME or your own certificate. Remove `sudo` and `--setup-panel` for a dry run.
3. Configure the exit first, then the ingress. Set up certificate trust for both ends. Use the locally generated private admin URL to sign in. Keep public subscription endpoints separate from admin access.
4. Link Edge and Exit, preview routing rules and verify the real egress. Set the default and explicit failure behavior. Issue the subscription with the desired profiles and limits, then test the URL and tunnel separately.
5. Back up state, keys and configuration before updates. Use the signed updater with an independently trusted root. Migrate manual installations separately.
