# Протоколы: сначала роль, потом выбор

Вход клиента и связь между нодами — два разных участка. Смена OpenVPN на другом
конце сети не превращает клиентскую VLESS-ссылку в OpenVPN-конфиг.

| Участок | Возможность 0.1.1 |
| --- | --- |
| Устройство → ARA Edge | Базовый VLESS + TLS; подтверждён независимым клиентом |
| Локальный Trojan-вход | Дополнительный явно включаемый режим Edge и панели; не включён по умолчанию и требует согласованной настройки |
| Edge → Exit | Типизированные VLESS/TLS, Trojan/TLS и Hysteria2-профили, с учётом роли и доступных возможностей |
| Сеть между нодами | OpenVPN или WireGuard backbone, managed apply/status и привязка к нужному интерфейсу |
| REALITY / Vision | Не объявляются частью принятого базового сценария 0.1.1; наличие полей или возможности upstream-движка не доказывает готовый ARA runtime |
| UDP приложений | Не является универсально поддержанной capability этого выпуска |

OpenVPN/WireGuard здесь не рекламируются как автоматически выдаваемый формат
обычной мобильной подписки. ARA запускает ограниченные собственные службы для
подготовленного backbone; системные пакеты и ключевой материал подготавливаются
оператором. Пользуйтесь поддержанным профилем, а не ручным включением незаявленного
флага движка.

## Проверка каждого хопа

1. Уточните роль профиля и адреса слушателей на обоих концах.
2. Проверьте сертификат, SNI/CA или собственную PKI/ключи backbone.
3. Проверьте canary, DNS и реальный запрос через выход.
4. Проверьте отказ выхода и ожидаемый failover/fail-closed.
5. Проверьте, что смена профиля не обнуляет общий учёт.

Справочник текущих команд: `ara node transport --help`, `ara link --help`,
`ara node backbone --help`. Автоматическое обновление компонентов и выбор
протокола не дают гарантии доступности каждого сайта в любой сети.
