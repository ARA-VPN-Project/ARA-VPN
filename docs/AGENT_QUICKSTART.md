# ARA VPN 0.1.1 · оператор и агент

## Что передать агенту

Передайте список разрешённых хостов, SSH-алиасы, роли, домены или IP, порты и ожидаемую схему маршрутизации. Укажите, где лежат сертификаты и ключи, и какие службы и порты уже заняты. Передавайте ссылки подписок и административные реквизиты отдельно. Укажите способ связи на случай потери SSH.

Пример задания без секретов:

> На Debian-хосте edge.example.com подготовь вход, на exit.example.com — выход. Пользуйся утверждёнными SSH-алиасами. Панель слушает TCP 29445, транспортный порт берётся из инвентаризации. Направь правило для video.example.com на exit.example.com и оставь остальное на локальном выходе. При отказе закреплённого выхода блокируй совпавший трафик. Сделай резервную копию, покажи diff и проверь запрос с клиента. Выпусти тестовую подписку, проверь загрузку и подключение, затем отзови её.

## Последовательность

1. Сверьте архитектуру, версии, свободное место, занятые порты и состояние служб. Сохраните резервную копию состояния с ограниченным доступом.
2. Установите нужные пакеты. Для новой панели запустите мастер. Для автоматизации мастера есть `configure-panel.sh HOST --port 29445 --bind 127.0.0.1 --self-signed`, `--acme` или пара `--cert PEM --key PEM`. Смена режима существующей панели — отдельная задача.
3. Проверьте рабочую топологию командами `ara node --help`, `ara link --help`, `ara topology --help` и `ara panel --help`. Используйте одинаковый каталог состояния для CLI и панели. Начинайте с выходов, затем настройте вход, связи и политику. Применяйте план с ожидаемым хешем и проверяйте фактическую версию конфигурации после перезагрузки службы.
4. Используйте `ara subscription --help` для создания, выдачи, ротации и отзыва. CLI и UI работают с одним набором данных. Пользовательская ссылка должна возвращать ожидаемый формат и обеспечивать рабочее подключение. Доступность конечного сайта и страну выхода фиксируйте отдельно.
5. Проверьте маршрут для двух классов доменов, состояние после отказа одного звена, статус служб и доступ к панели. При нарушении инварианта откатите только затронутые ресурсы. Запишите версии, результаты и оставшиеся ограничения без токенов и секретных URL.

## English

Give the agent an explicit host allowlist, node roles, bind addresses, certificate paths, routes and a recovery channel. Take an inventory and a restricted backup first. Install by role, configure exit then ingress, review the plan and apply its expected hash. Verify HTTPS, the actual client egress, subscription loading and connectivity, and the chosen failure behavior. Report versions and observable evidence without credentials.

## Дополнения 0.1.1

Публичная страница использует public-page.json в каталоге панели. Подготовьте JSON с mode, title, text и выполните ara-control --state-dir STATE --set-public-page FILE от пользователя службы. Для HTTP-автоматизации используйте GET/POST /api/v1/public-page с отдельным bearer-токеном. В журнал и аргументы не выводите секреты. Страну в CLI по-прежнему задавайте стандартным двухбуквенным кодом. UI подставляет его из выбранного названия.

Главная панель, выдающая подписку, должна управлять общими ограничениями пользователя и отдельными ограничениями каждой конфигурации, в том числе выданной связанной ARA-нодой. При приёмке обязательно проверяйте доставку прав и реальный поток на ноде. Произвольная сторонняя ссылка может обслуживаться внешним оператором, её лимиты требуют отдельной интеграции.

## Отдельное устройство в подписке

Один ключ не позволяет достоверно отличить несколько физических телефонов, на которые скопировали один конфиг. Для отдельного учёта выдавайте отдельную identity: в карточке подписки нажмите «Добавить устройство», задайте имя и передайте этому устройству его ссылку/QR. Повторное открытие основной ссылки не создаёт новый слот.

Те же действия доступны агенту в каталоге состояния панели:

```sh
ara subscription device-add --id SUBSCRIPTION_ID --name Phone --base https://panel.example:29445 --json
ara subscription device-link --id SUBSCRIPTION_ID --device DEVICE_ID --base https://panel.example:29445 --json
ara subscription device-revoke --id SUBSCRIPTION_ID --device DEVICE_ID --json
```

Вывод выдачи содержит секретную ссылку: передавайте его получателю приватно, не прикладывайте к отчётам. Лимит слотов проверяется атомарно; отзыв освобождает слот и не отзывает другие ключи подписки. Общий бюджет подписки продолжает действовать для всех её устройств и профилей.

## Имена и отдельные ограничения конфигураций

В «Конфигурациях» карточки подписки задайте имя, которое увидит клиент. Технические ноды и панель-источник отображаются отдельно: одинаковые стандартные имена можно заменить, не меняя маршрут и identity. Пустое дополнительное ограничение не сужает общий бюджет; 0 запрещает передачу. Объём профиля учитывается за календарный месяц UTC, загрузка и отдача суммируются.

Для автоматизации подготовьте JSON-массив с полями kind, node_id, edge_node_id (для проходного пути), name, download_bps, upload_bps, limit_bytes и примените:

```sh
ara subscription set-profiles --id SUBSCRIPTION_ID --profiles-file profiles.json --json
```

При неожиданном завершении Edge неотчитанная резервация профиля остаётся списанной консервативно. Нормальное закрытие возвращает неиспользованный остаток. Ошибка записи/связи не разрешает неучтённый трафик. При переносе владельца обязательства профилей передаются вместе с общим расходом. Не меняйте техническую идентичность маршрута только ради переименования.

## Публикация Edge из панели

В разделе «Сеть → Конфигурация входной ноды» выберите вход, связанную панель с правом quota и подписку. Укажите доступный ноде HTTPS-адрес владельца, слушатель, DNS в области выхода и пути сертификата/ключа/CA **на входной ноде**. Проверьте план и его хеш, затем опубликуйте. API использует те же EdgeConfigPlan/Apply, что `ara node edge-config plan|apply`; неверный хеш отказывает до публикации.

Публикация — доставка желаемого состояния, а не подтверждение рабочего туннеля. На подготовленной ноде выполните штатный `ara edge sync` с установленным путём и unit, затем проверьте serving receipt и реальный запрос клиента. Выходные слушатели и адаптеры должны быть подготовлены отдельно; этот выпуск не предоставляет универсального удалённого root-доступа из панели.
