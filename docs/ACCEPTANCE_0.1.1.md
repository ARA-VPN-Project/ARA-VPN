# Приёмка ARA VPN 0.1.1 · 10 ноября 2026

**Решение: текущая версия технически принята в согласованном владельцем объёме.** Поддерживаемый основной сценарий — native Debian с UI и CLI, предварительно подготовленными входами/выходами и стандартным сторонним VPN-клиентом. По решению владельца телефонные приложения, Docker runtime и полевые проверки не блокируют эту приёмку. Лицензия собственного кода — AGPL-3.0-or-later; публикация не выполнялась.

Принятие текущего объёма не означает появления новых возможностей. Первоначальная подготовка транспортных слушателей/адаптеров всё ещё требует консоли. Публикация Edge-плана из панели — не автоматический bootstrap пустого удалённого хоста. Установщик не открывает универсальный root-доступ.

## Свежая установка и браузер

На тестовом Debian удалены только пакеты и прежнее состояние ARA с сохранением резервной копии. Старая сохранённая операторская настройка мешала чистому мастеру: он корректно отказался её затирать. Файл перенесён в backup, после чего выполнено настоящее скачивание установщика и четырёх пакетов с отдельного HTTPS-зеркала. Проверены SHA-256, идентичность пакетов и штатная установка через apt/dpkg. Это эмуляция будущей GitHub-доставки, а не опубликованный GitHub Release.

Выбраны IP 127.0.0.1 и порт 29445 по умолчанию; для браузерной проверки импортирован прежний доверенный лабораторный сертификат. Новая форма браузерного предупреждения не обходилась. Мастер вывел полную ссылку, логин и пароль; создан нейтральный путь connect. Скачивание и мастер выполнены через SSH: инструмент управления приложением «Терминал» отказал в доступе. Последующий вход и создание ноды, выбор страны, настройка адреса, создание пользователя/подписки, выбор профиля/лимита, получение ссылки и QR выполнены через интерфейс браузера.

Проверка скачивания выявила пропуск ARA_SUB_CA в настройках мастера. Исправленный мастер устанавливает ARA_SUB_CA=system. Эта же настройка применена к свежей тестовой установке; после перезапуска стандартная подписка отдаёт HTTP 200 и корректный VLESS URI. Для собственного CA его надо установить в доверие клиента; TLS-проверка не отключается. JSON-каталог также проверен. Старое состояние ARA сохранено отдельно, боевые серверы в этой кампании не менялись.

## ARMv7: выполнение, а не только сборка

QEMU user-mode из официального Debian-пакета: 10.0.13, CPU cortex-a7. Собраны четыре armhf-пакета 0.1.1, GOARCH=arm, GOARM=7. Engine sing-box 1.14.4 соответствует digest ARMv7 из third_party.lock.json. Исполнялись ARM-бинарники на ядре тестового amd64 Debian: это не загрузка отдельной ARM-системы и не физический ARM-сервер.

| Проверка | Результат |
| --- | --- |
| Эмулируемый engine: запуск и version | PASS |
| core/health, core/policy, core/routing, core/limits | 4/4 пакета PASS |
| core/transportprofile, core/update | 2/2 пакета PASS |
| internal/controlstore, internal/tlswizard | 2/2 пакета PASS |
| ARM CLI из итогового пакета, версия 0.1.1 | PASS |
| Независимый native sing-box-клиент → ARM ARA Edge → ARM sing-box-выход → Internet | PASS |
| HTTPS example.com и Google через этот путь | PASS |

Для wire-проверки использован UUID и адрес из стандартной ссылки, выданной через свежую панель. Клиентский URI разобран независимо. Серверный тестовый runtime подготовлен консолью в отдельном каталоге, слушатели только loopback; это не доказательство автоматического развёртывания сервера кнопкой. TLS проверяется с явно доверенным CA. Все временные процессы после проверки остановлены. Race detector для linux/arm не поддерживается: ARM-тесты выполнялись без -race; race-набор отдельно проверен на native Debian.

## Накопленные подтверждённые результаты

- Полный Debian race-набор: 26 тестируемых пакетов PASS после исправления локальной привязки устройств; целевые Mac control/service/store также PASS.
- Лабораторная федерация из установленных пакетов: 65/65 PASS, включая прямые/проходные профили, два разных устройства, отзыв, лимиты, перенос, ротацию/follow и Edge plan/apply API. Этот прогон предшествовал локальной правке связи устройства с несколькими подписками; после неё прошли целевая регрессия, полный native race-набор и действующие серверные проверки. Не считать эти прогоны одним общим snapshot.
- Bounded soak: 60 секунд, 55 успешных запросов, 0 ошибок. Это не длительный soak.
- TG и AutoService: обновлены до 0.1.1, сохранены существующие ключи/подписки/расход, проверены российский и немецкий выходы; MTProto/Xray и Caddy/NaiveProxy сохранены. Операционные сведения и ключи не включены в публичный архив.
- UI: desktop 1440×1000 и mobile 390×844, шесть разделов без общего горизонтального переполнения; центрирование входа 0 px по обеим осям; сохранение имён и ограничений конфигураций, повторное открытие ссылки/QR. Скриншоты — в галерее.

Одинаковый ключ на двух телефонах считается одним зарегистрированным устройством. Для отдельного учёта выдаётся отдельная identity. Общий бюджет подписки действует для всех её устройств и профилей. Профильный объём — месяц UTC; неотчитанные резервации после сбоя учитываются консервативно. Rate-права разных нод могут сходиться до TTL 30 секунд; отсутствие права не превращается в unlimited.

## За пределами этой приёмки

Физический ARMv7, отдельное ARM-ядро/systemd, конкретные приложения iOS/Android, Docker runtime, публичный ACME нового мастера, загрузка из настоящего GitHub Release и полевые DPI/географические замеры. Поддержка стандартного протокола подтверждена независимым клиентом, но совместимость с каждым приложением не заявляется. Внутренний UDP и другие ранее отмеченные UNSUPPORTED_CAPABILITY не становятся поддержанными от решения о приёмке.

Лицензия выбрана и материалы распространения оформлены: [лицензионная приёмка](LICENSE_ACCEPTANCE_0.1.1.md). Source-ассеты должны сопровождать публичные бинарники. Публикация выполняется отдельно от технической приёмки; текущие адреса — в PUBLICATION.md.
