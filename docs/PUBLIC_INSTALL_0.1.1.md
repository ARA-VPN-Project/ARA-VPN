# Установка ARA VPN 0.1.1 с GitHub · 10 ноября 2026

**PASS: настоящая установка опубликованных пакетов на тестовый Debian amd64.**
Скачивание выполнялось с GitHub, без локальной подмены URL и без ручного
редактирования установленной конфигурации.

## Проверенный путь

1. Прежняя тестовая установка ARA сохранена в закрытой резервной копии.
   Удалены только её пакеты, состояние и прежние ссылки автозапуска.
   Соседние приложения, SSH и основной маршрут не перенастраивались.
2. Выполнена команда из актуального README: `curl …/main/install.sh | sh`
   в root-сессии с терминалом. Для обычного пользователя команда использует sudo.
3. Проверены pinned bootstrap, архитектурный manifest и контрольные суммы
   четырёх .deb, затем выполнена реальная установка apt/dpkg.
4. В мастере приняты значения по умолчанию: 127.0.0.1, порт 29445 и новый
   локальный сертификат. Мастер вывел полный приватный URL, имя и пароль.
5. Проверен HTTPS с явным доверием созданному сертификату, включая имя/IP;
   проверка TLS не отключалась. Для браузера на другом устройстве этот
   сертификат нужно добавить в доверие либо выбрать сертификат доверенного CA.
6. Проверены вход выданными реквизитами, cookie, защищённый API, CSRF и запись
   тестового пользователя. После перезапуска ARA данные и реквизиты сохранились.
   Тестовая запись затем удалена, панель оставлена без тестовых пользователей.

## Исправления, проверенные этим проходом

- Лицензионные копии больше не содержат посторонний Go-тест как уведомление.
- Пакеты собраны каноническим `dpkg-deb`; проверка дополнительно отклоняет
  дочерний каталог, записанный до родителя. Все восемь пакетов полностью распакованы.
- Поддерживаемый launcher передаёт мастеру управляющий терминал при `curl | sh`.
- Bootstrap различает известное состояние «не установлен» после purge и
  действительно частичную установку; частичные состояния по-прежнему отклоняются.

Запуск команды установки не равен автоматическому bootstrap транспорта между
произвольными нодами. Входы и выходы подготавливаются отдельно по руководству;
проверка нового туннеля после этого остаётся отдельным шагом. В этом проходе
перезапускалась только ARA, полная перезагрузка виртуальной машины не выполнялась.
ARMv7 и Docker не объявляются проверенными этим amd64-сценарием.
