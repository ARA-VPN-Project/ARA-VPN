# ARA VPN: правила работы

Работать в этом проекте. Текущий scope — Debian-клиент и Debian-сервер, native и Docker. Остальные платформы — только контракты и документация до команды пользователя. Не трогать соседние проекты.

- Прочитать README.md, docs/GETTING_STARTED.md и docs/RELEASE_0.1.1.md перед реализацией.
- Работать только на хостах, явно разрешённых владельцем задачи. Сначала read-only инвентаризация, затем резервная копия, plan и проверяемый откат.
- Не менять основной маршрут, SSH, DNS или чужие службы. Сетевые интеграционные тесты запускать в изоляции или по явно разрешённому сценарию.
- Передавать агенту адреса, роли и пути к локальным секретам по защищённому каналу. Не включать ключи, подписки, пути панели и credentials в команды с выводом, артефакты и Git.
- Для автоматизации использовать CLI с `--json`, стабильные коды ошибок и plan/apply с проверкой хеша. Проверить статус, фактический маршрут, публичный TLS и доступность управления после применения.
- Никакой собственной криптографии, отключения проверки сертификатов, общего root UI, открытого management API или универсального shell RPC.
- Пользователь согласовал автоматический fallback: foreign pool → RU Exit, без вопросов на каждый отказ. Не заменять его скрыто на BLOCK или LOCAL_DIRECT. Строгая политика допустима только как явно выбранный дополнительный режим.
- Все пользовательские строки, ошибки и onboarding на RU и EN; коды ошибок стабильны.
- Публичные JSON примеры содержат только TEST-NET и .invalid/.example, без секретов. Частные сведения разрешённого lab хранить в отдельной документации/локальном inventory, не включать в публичные шаблоны и релизы.
- Отчёт обязан различать реализовано, проверено локально, требует lab, запланировано. Не заявлять работающий VPN по наличию интерфейса.
- Не скачивать и не устанавливать зависимости/ядра автоматически при чтении проекта. Версии и supply chain согласуются инженерно в locks по результату проверки.

Приоритеты: безопасность, скорость, удобство. CLI равноправен UI. Обязательны account/device rate и quota limits; RU fallback не обходит лимиты. Не расширять MVP в систему массовой оркестрации нод.
